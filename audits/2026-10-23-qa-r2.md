## Blocker

### QA-016: Every generic list, item, create and edit page renders with each field shifted one type over, so Models is unusable
- **Area:** dashboard
- **URL:**
  - Lists: `/dashboard/appointments`, `/dashboard/services`, `/dashboard/users`, `/dashboard/locations`, `/dashboard/payment-providers`, `/dashboard/message-templates`, and the others.
  - Item pages: `/dashboard/appointments/<id>`.
  - Create pages: `/dashboard/resources/create`, `/dashboard/users/create`.
- **Steps:**
  1. Sign in as the admin.
  2. Open **Models → Users** (or any list).
  3. Open `/dashboard/appointments/cmvlo5mkd001iqq01acvgfmlh` (an appointment that exists).
  4. On **Resources**, click **New resource**.
- **Expected:**
  - Lists load their rows, and item pages show the record.
  - Create and edit forms use the right widget per field, as in E-commerce: text inputs for text, selects for selects, number inputs for integers, date pickers for timestamps, and relationship pickers for relationships.
- **Actual:**
  - Every list shows "Failed to load items: Unable to complete the request. Please try again." The console logs `Dashboard operation failed (details redacted).`
  - The existing appointment shows "Not found · The item with ID … doesn't exist, or you don't have access to it."
  - **Create Resource** shows the wrong widgets:
    - `Type` (select) is a number input, and the console warns `The specified value "room" cannot be parsed`.
    - `Revision` and `Capacity` (integers) are date-time pickers.
    - `Is Active` and `Is Public` (checkboxes) are selects.
    - `Maintenance Due At` and the other timestamps are JSON textareas.
    - `Readiness Status` is a number input and warns `"acceptance_testing" cannot be parsed`.
    - Every relationship (`Location`, `Services`, …) is a locked "Auto-generated · autoincrement" id field.
  - `/dashboard/users/create` shows the same pattern, with the warning `"not_started" / "active" cannot be parsed`.
- **Root cause (confirmed):**
  - The live admin meta for `Resource` uses these view indexes: `id`=0, relationship=1, text=2, json=3, timestamp=4, integer=5, select=6, checkbox=7. Those match `features/keystone/view-order/index.ts`, whose `VIEW_ORDER` **starts with `"id"`**.
  - The shared `features/dashboard/views/getFieldTypeFromViewsIndex.ts` builds `['id', ...VIEW_ORDER]`. That adds a second `id`, so index *n* maps to type *n−1*: relationship→id, text→relationship, integer→timestamp, and so on. Those wrong controllers also build invalid GraphQL selections, which is why lists and items fail to load.
  - E-commerce (`openfront/features/keystone/view-order/index.ts`), Restaurant and Salon all generate `VIEW_ORDER` **without** `id`.
- **Likely files:**
  - `features/keystone/view-order/generate-view-order.ts`: drop the id-field view from the emitted list, as E-commerce does.
  - The regenerated `features/keystone/view-order/index.ts`.
  - The shared `getFieldTypeFromViewsIndex.ts` is parity-locked, so fix the generator, not the shell.
- **Why it's a blocker:** Users, roles, locations, the practice, payment providers, message templates and gift cards still have no platform screen. Models is the only way to manage them, and an edit saved through these forms would write the wrong types.

### QA-017: Guest booking requests from the storefront can't be confirmed, cancelled or contacted by staff
- **Area:** dashboard / storefront
- **URL:** `/book` (as a signed-out visitor), then `/dashboard/platform/appointments/cmvlnz5r4001bqq01kzxfka9j`
- **Steps:**
  1. Signed out, book Dermaplaning → Lena Park → Wed Oct 28 → 10:00 AM, enter name, email and phone, then click **Request appointment**. The page says "Request sent · Awaiting confirmation".
  2. As the admin, open Appointments → **Pending** → that request.
- **Expected:** The front desk sees the client's name, email and phone and can **Confirm**, **Cancel** or **Record no-show**, as it can for a signed-in client's booking.
- **Actual:**
  - The header and the Client card say **"Client restricted"**, so staff can't see who asked or how to reach them.
  - The Scheduling card says "Scheduling is unavailable. Retry without replacing a pending update." The Action select is empty and **Save status** is disabled.
  - `medspaAppointmentSchedule(appointmentId:…)` returns `INTERNAL_SERVER_ERROR "Unexpected error."`
  - The request sits in Pending forever and holds Lena's 10:00 slot.
  - The default storefront booking path is a guest booking, so this hits most real requests.
- **Root cause:**
  - `bookAppointment` creates guest bookings with `client: null` and keeps the contact in `guest` metadata.
  - `assertAppointmentSchedulingAuthority` throws when `!header.client?.id` (`features/keystone/appointmentSchedulingAuthority.ts:51`).
  - `AppointmentWorkflowPage.tsx:34` falls back to "Client restricted" when there's no `client.user`.
- **Likely files:**
  - `features/keystone/appointmentSchedulingAuthority.ts`
  - `features/keystone/mutations/bookAppointment.ts`: either create or attach a practice Client for guest requests, or support guest-only appointments in scheduling.
  - `features/platform/appointments/screens/AppointmentWorkflowPage.tsx`: show the guest name and contact to staff.

### QA-018: Checkout can't complete on production because the tax rate comes only from an unset env var
- **Area:** dashboard
- **URL:** `/dashboard/platform/checkout/cmvlo5mkd001iqq01acvgfmlh`
- **Steps:**
  1. Confirm a signed-in client's appointment, then **Check in client**.
  2. Click **Start checkout**.
- **Expected:** Record a cash payment for $95, as E-commerce lets a merchant take payment, with tax set up somewhere the merchant can reach.
- **Actual:**
  - The page shows "Tax: Not configured · Treatment total: Not configured · Tax rate is not configured." The submit button reads **Checkout unavailable** and is disabled.
  - Nothing in Storefront settings, Practice setup or any platform page sets a tax rate.
  - As a result, no payment can be recorded, no commission accrues, and Reports stays at "No settled activity".
- **Root cause:**
  - `configuredTaxRate()` in `features/keystone/checkoutInput.ts` reads only `process.env.TAX_RATE` and throws when it's unset.
  - `calculateCheckoutTotals` (`features/platform/checkout/actions/checkout.ts:206`) turns that into `tax: null`, and `CheckoutCard` (`features/platform/checkout/screens/CheckoutQueuePage.tsx:68-73`) then blocks checkout.
  - Onboarding promises "Published and bookable" but never sets a rate.
- **Likely files:**
  - `features/keystone/checkoutInput.ts` and `completeAppointmentCheckout.ts`: read a per-practice or per-location tax rate, which a med spa often sets to 0 for services.
  - The onboarding seed: set an explicit rate, e.g. `0`.
  - A tax field in Practice or Storefront settings.
